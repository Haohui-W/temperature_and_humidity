## Why

疾控现场工作人员需要更快地采集检查点位的温湿度，并把结果整理成可填报内容，减少额外硬件携带和重复手工录入。该 MVP 基于 `docs/技术方案.md`，把当前 Android 模板工程推进为可演示、可验证的第一版产品路径：一键本地估算、点位采集、本地保存和待复制结果生成。

## What Changes

- 将模板 App 改造成面向现场工作的 MVP：支持发起测量、查看估算温湿度、确认点位名称并准备填报。
- 增加麦克风权限处理；当权限或设备输入不可用时，展示明确的降级模式。
- 增加本地信号采集与估算框架，覆盖声学估算、热特征估算、融合温湿度结果、置信度和质控结果。
- 在设备支持时通过语音识别采集点位名称，并允许用户在填报前手动修正。
- 增加本地填报辅助流程：保存报告草稿/历史记录，并生成用户可复制到疾控填报系统的文本结果。
- 增加录音最小化隐私行为：音频仅在本地处理，只在测量期间保留于内存，处理后清理，App 不上传原始音频。
- 本 MVP 不包含：估算模型的生产级标定、模型/机型库的后台 fleet 管理、正式合规认证、在线 API 对接、后台同步，以及对第三方填报系统的自动填充。

## Capabilities

### New Capabilities

- `environment-measurement`：覆盖一键测量会话、设备信号采集、声学/热特征估算、多模态融合、置信度评分、质控失败和降级测量模式。
- `cdc-reporting`：覆盖点位名称采集与修正、报告创建、本地加密存储、待复制结果生成，以及用户可见的报告状态。
- `privacy-permissions`：覆盖运行时权限请求、权限拒绝行为、音频数据最小化、本地音频处理、数据保留限制和面向用户的隐私说明。

### Modified Capabilities

- 无。当前项目的 `openspec/specs/` 下还没有既有 OpenSpec 能力。

## Impact

- Android 应用代码位于 `app/src/main/java/com/haohui/temperature_and_humidity`，预计拆分为 UI、测量、填报、存储、隐私/权限等包。
- Android 资源位于 `app/src/main/res`，需要用 MVP 测量与填报流程替换模板页面，同时沿用当前 XML/ViewBinding 风格。
- `AndroidManifest.xml` 需要声明麦克风权限，并可能声明可选传感器能力。
- Gradle 依赖可能需要增加本地存储、加密、语音识别集成和测试支持。
- 本地持久化需要保存报告草稿/历史记录和复制状态；MVP 不应保存原始音频。
- 在可行范围内补充估算/融合逻辑、权限与降级模式、报告状态流转、复制文本生成规则的测试覆盖。
