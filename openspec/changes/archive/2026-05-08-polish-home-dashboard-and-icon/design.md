## Context

当前应用已经具备测量、报告保存和复制的 MVP 主流程，但 UI 仍是线性表单：原生 toolbar、纵向文字和按钮堆叠、默认主题色，以及 Android Studio 默认启动图标。参考截图呈现的是更偏业务首页的仪表盘结构：白色圆角容器、三列环境参数卡片、描边刷新按钮和底部导航。

这次变更只处理产品观感和 App shell，不改变测量算法、报告模型、权限隐私或本地存储逻辑。实现仍沿用当前 XML 布局、ViewBinding、Material Components 和 Navigation。

## Goals / Non-Goals

**Goals:**

- 首页第一屏接近参考截图中的“环境参数”仪表盘视觉。
- 温度、湿度、气压以三张卡片展示，并复用现有测量结果数据更新温湿度。
- 一键测量入口改为接近截图的刷新/描边按钮，同时继续触发现有测量流程。
- 底部展示“首页、任务、物资、采样、更多”五个入口，首页为真实业务页，其余为占位空白页。
- 替换默认 Android launcher 图标，使用临时 emoji 风格图标，便于 APK 演示辨识。

**Non-Goals:**

- 不实现任务、物资、采样、更多的实际业务功能。
- 不展示参考截图中的红色标注框和红色说明文字。
- 不迁移到 Jetpack Compose，不引入新的导航框架或 UI 大型依赖。
- 不改变测量估算、质控、报告保存、复制文本和隐私权限行为。

## Decisions

### 1. 保持 XML/ViewBinding，实现一个截图风格首页

首页布局继续使用 XML，重组为一个浅灰背景上的白色圆角主容器。容器内保留“环境参数”标题，下面用三列卡片展示温度、湿度和气压。温度与湿度绑定现有 `textTemperature` 和 `textHumidity` 更新逻辑；气压首版展示 `-- kPa` 占位值，不伪造测量数据，也不阻塞测量主流程。

备选方案是迁移 Compose 或引入新的 UI 组件库。当前需求是视觉打磨，不需要架构迁移；沿用 XML 能降低风险，并减少对现有 ViewBinding 代码的影响。

### 2. 将现有测量按钮视觉改造成刷新按钮

保留 `buttonMeasure` 的业务语义和点击处理，调整为全宽描边按钮，并使用“刷新数据”或同义文案。这样实现可以复用现有权限请求、测量执行和状态更新逻辑。

备选方案是新增单独刷新控件再桥接旧按钮逻辑。它会增加状态同步和测试负担，收益不明显。

### 3. 底部导航只提供视觉入口和占位页面

Activity 层增加底部导航或等价 XML 结构，五个入口分别为首页、任务、物资、采样、更多。首页导航到现有测量 Fragment；其他入口进入同一个或多个空白占位 Fragment，展示极简空状态，不承诺业务功能。

备选方案是直接隐藏未实现入口。用户明确希望保留截图风格，因此保留入口更符合演示目标；通过空白页避免误导为已完成模块。

### 4. 启动图标使用临时 emoji 风格资源

Android launcher icon 不能直接把 emoji 字符作为 Manifest 图标引用，因此实现时应生成或绘制可打包资源：优先使用简单 vector 或 raster asset 表达 emoji 风格，例如温度计、水滴、参数卡组合。Manifest 继续引用 `@mipmap/ic_launcher` 和 `@mipmap/ic_launcher_round`，替换其背后的资源内容即可。

备选方案是继续使用默认图标或引入正式品牌设计。默认图标不适合演示；正式品牌设计超出当前范围，临时 emoji 风格足够支撑迭代。

### 5. 主题色和控件样式集中在资源层

新增或扩展颜色、shape、文字样式和按钮样式资源，使首页背景、卡片、描边按钮、底部导航色彩统一。业务 Fragment 代码只负责数据绑定和点击事件，避免把视觉细节硬编码进 Kotlin。

备选方案是在布局中大量内联颜色和形状。资源集中管理更利于后续替换正式视觉方案。

## Risks / Trade-offs

- 截图是静态参考且含标注 → 以用户确认的规则为准：红框红字不进入 App，只复刻首页结构和气质。
- 气压数据当前业务链路未必稳定提供 → 首版显示 `-- kPa` 占位值，后续再接入真实来源；不得影响温湿度测量。
- 底部入口为空白页可能让用户误以为模块缺失 → 占位页应保持简洁，避免展示假功能。
- emoji 风格 launcher icon 可能受设备裁剪和 adaptive icon 蒙版影响 → 使用安全区域内居中的图形，并检查圆形/方形图标都可辨识。
- UI 改动主要靠人工验收 → 至少运行构建验证资源可编译，并尽量用真机或预览截图检查布局不溢出。

## Migration Plan

1. 增加首页所需颜色、shape、文字和按钮样式资源。
2. 重构首页 XML 布局为环境参数卡片结构，保持现有 ViewBinding id 的兼容或同步更新 Kotlin 绑定。
3. 增加底部导航和空白占位 Fragment/布局，并更新 navigation graph。
4. 替换默认 launcher icon 资源为临时 emoji 风格图标。
5. 运行 `./gradlew :app:assembleDebug` 验证资源和代码可编译。
6. 若需要回退，可恢复原始布局和默认图标资源；业务数据和本地存储不需要迁移。
