## Why

`docs/技术方案.md` 描述的是完整产品目标，但当前 App 只实现了 MVP 闭环：本地估算、点位确认、本地加密历史，以及可复制的填报文本。本变更把技术方案里尚未真实落地的能力转成明确、可审阅、可验证的 OpenSpec 范围，方便后续逐项判断是实现、延期还是移除。

## What Changes

- 将当前占位式声学估算升级为面向生产的声学测量链路：立体声 PCM 校验、左右声道拆分、JNI/C++ TDOA 互相关、声速推导、结合气压反推温湿度、SNR/输入质量置信度，以及音频内存清理校验。
- 增加设备/机型适配能力：本阶段先内置静态麦克风间距表和未知机型默认值；云端维护和动态更新作为后续能力，不在当前实现范围内。
- 将热特征估算从固定启发式规则升级为演示模型边界：覆盖电池温度、CPU thermal zone、CPU 负载稳定度、输入缺失处理和置信度调整，但明确标注为未标定演示估算。
- 扩展融合与质控：增加声速合理性检查、来源降级规则、置信度阈值，以及用户可见的重测/降级原因说明。
- 补齐权限拒绝后的热特征降级体验：麦克风被拒绝时隐藏/跳过声学路径，展示热特征模式说明，并在 specs 阶段明确是否采用技术方案中的“60 秒出数”等待。
- 将 MVP 阶段“绝不发起网络请求”的填报边界，调整为本地存储优先，并增加一个可关闭的象征性网络调用：使用 httpbin 等公开测试端点验证网络权限、请求构造和错误处理；在疾控 API 未提供前，不实现也不声称真实提交。
- 将本地报告存储从加密 SharedPreferences 升级为 SQLite 持久化，并增加网络演示记录表：记录 httpbin 调用是否成功、失败原因和响应摘要；不引入真实同步队列。
- 增加验证与合规证据要求：凡是不能只靠代码证明的能力，例如精度、机型覆盖率、现场验收、隐私与监管合规，都必须有对应证据或评审门禁。
- 尽量保留现有 MVP 用户流程：一键测量、语音或手动点位采集、质量/置信度可见，以及在音频、热特征、气压、网络或 API 不可用时可降级使用。

非目标：

- 在没有验证材料和外部批准前，不声明具体温湿度精度、机型覆盖百分比或已完成法律/监管认证。
- 不上传原始测量音频。环境测量音频仍然只在本地内存中处理，并在处理后清理。
- 不硬编码真实疾控账号、生产接口地址或未确认的第三方系统行为。
- 不实现云端机型库、云端校准更新或后台 fleet 管理；本阶段只使用 App 内置静态机型表。
- 不实现第三方填报系统自动填表、联网后自动同步或真实提交状态；这些能力必须等真实疾控 API/系统边界明确后另开变更。

已知卡点与前置依赖：

- 疾控填报 API 当前不存在或未提供正式合同，因此真实 API 提交不进入当前实现范围。当前只允许保留本地存储，并可增加一个面向开发/演示的 httpbin 网络调用，用于验证网络权限、请求序列化、响应解析和失败提示；真实提交能力必须等接口地址、认证方式、字段协议、错误码和测试环境明确后另开变更。
- 声学/热特征预训练模型当前不存在，因此不能直接实现文档中 `acousticModel.predict(...)` 或 `thermalModel.predict(...)` 的生产能力；本变更先做演示模型和模型接口，输出必须标注为未标定/演示估算，并保留后续替换为真实模型的边界。
- 云端机型麦克风间距库和校准数据当前不存在，不能声称“150+ 机型覆盖”或“误差≤0.1℃”；本阶段先按技术方案内置静态表：华为 P50/P40/Mate40 为 5.0cm，小米 13/12/11 为 4.8cm，OPPO Find X5/Reno8 为 4.9cm，vivo X80/X70/S15 为 5.1cm，荣耀 Magic4/60/50 为 4.9cm，红米 Note12/11 为 4.7cm，未知机型默认 5.0cm。
- JNI/C++ TDOA 算法必须在本变更内完成工程实现，但准确性依赖真实双麦采样、机型参数和标定数据；没有现场/实验室数据前，只能验证算法执行正确性，不能验证测量精度。
- 合规认证不是代码任务，必须依赖外部隐私、安全和业务评审材料；App 只能提供数据最小化、权限说明、日志/存储边界等技术支撑。

## Capabilities

### New Capabilities

- `device-model-adaptation`：覆盖内置静态麦克风间距机型库、未知机型默认值、匹配规则和校准数据缺失时的展示限制；云端更新暂不实现。
- `network-demo`：覆盖 httpbin 等公开测试端点的象征性网络调用、请求/响应摘要、失败提示和可关闭配置。
- `validation-compliance`：覆盖实验室/现场验证证据、算法能力验收标准、隐私评审门禁，以及未验证性能声明的展示限制。

### Modified Capabilities

- `environment-measurement`：把声学、热特征、融合、气压和质控要求从 MVP 估算器升级为技术方案中的完整测量链路。
- `cdc-reporting`：保持报告本地保存与复制为主流程，将本地报告迁移到 SQLite 存储，并增加“网络演示调用”边界和结果状态；真实疾控 API 提交继续保持未实现/不可声明。
- `privacy-permissions`：增加网络演示调用的权限与隐私边界、模型/校准更新隐私约束，并更清楚地区分本地测量音频和可选系统语音识别。
- `home-dashboard-ui`：增加高级测量阶段、降级/失败原因、网络演示状态、校准新鲜度，以及必要的验证免责声明展示。

## Impact

- 影响 Android App 代码，主要包括 `app/src/main/java/com/haohui/temperature_and_humidity` 下的 `measurement`、`reporting`、`storage`、`privacy` 和 UI Fragment/资源。
- Gradle/构建配置需要增加 JNI/C++ native build 支持、额外测试支持，以及网络/调度相关依赖。
- `AndroidManifest.xml` 需要审查并增加网络权限和可选功能声明，同时不能把麦克风、气压计或网络可用性变成阻断本地降级流程的硬性条件。
- 需要新增或迁移本地 SQLite 数据结构，用于报告历史、设备校准元数据、网络演示记录和验证/合规标记。
- 真实填报集成依赖外部 API 合同、认证方式、端点配置和测试环境；在这些条件不存在时，只能使用 httpbin 等测试端点做象征性网络验证。
- 测量精度与合规声明依赖外部校准数据、代表性机型覆盖、现场测试执行和评审材料。
